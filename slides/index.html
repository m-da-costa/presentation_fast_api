06 · FastAPI

Parâmetros no endpoint

parâmetro de caminhopython
@app.get("/produtos/{produto_id}")
def buscar_produto(produto_id: int):
    return {"produto_id": produto_id}
GET/produtos/10{"produto_id": 10}
GET/produtos/abc422

O type hint faz o trabalho. produto_id: int faz o FastAPI converter e validar o valor da URL. Uma chamada a /produtos/abc recebe um 422 com mensagem clara — sem você escrever uma linha de validação.

06 · FastAPI

Endpoint POST e validação com Pydantic

main.pypython
from pydantic import BaseModel

class Produto(BaseModel):
    nome: str
    preco: float

@app.post("/produtos")
def criar_produto(produto: Produto):
    return produto
corpo da requisição{ "nome": "Mouse", "preco": 150.0 }
  • Campo faltando → 422
  • Tipo errado → 422
  • O modelo vira documentação

No POST os dados vêm no corpo da requisição, não na URL.
Mnemônico: Field no corpo, Query na URL.

06 · FastAPI · a pegadinha

A ordem das rotas importa

Uma armadilha que pega todo mundo — inclusive quem escreveu esta aula.

❌ erradopython
@app.get("/produtos/{produto_id}")

✅ certopython
@app.get("/produtos/media")

@app.get("/produtos/{produto_id}")
def buscar_produto(produto_id: int): ...
GET/produtos/media (na versão errada)o FastAPI tenta converter "media" em int422

O FastAPI testa as rotas de cima para baixo e para na primeira que casa. /produtos/{produto_id} casa com qualquer coisa depois de /produtos/. Regra prática: rotas com caminho fixo vêm antes das rotas com parâmetro.

06 · FastAPI

Boas práticas

1

Nomes claros para endpoints

/produtos, não /getProdutosNovo

2

Usar o método HTTP correto

GET consulta, POST cria, PUT atualiza

3

Validar os dados recebidos

Pydantic faz a maior parte do trabalho

4

Retornar o status adequado

201 ao criar, 404 quando não existe

5

Tratar erros

mensagem clara em vez de stack trace

6

Autenticar quando necessário

nem todo dado pode ser público

7

Nunca versionar segredos

tokens e senhas fora do código

8

Documentar os endpoints

descrições e exemplos nas funções

9

Versionar a API

/api/v1/… para não quebrar clientes

10

Separar regra de negócio

o endpoint chama; a lógica mora fora dele

Ciência de Dados não termina no DataFrame.

Dados precisam ser obtidos, processados, analisados, visualizados e, com frequência, disponibilizados para outros sistemas.

07 · Exercício

Desafio

Uma API devolve a seguinte lista de produtos:

resposta da APIjson
[
  {"produto": "Notebook", "preco": 4500},
  {"produto": "Mouse", "preco": 150},
  {"produto": "Monitor", "preco": 1200}
]

Dica: se não houver uma API disponível, comece com a lista já em Python. O foco do exercício é o encadeamento das etapas, não a rede.

Sua tarefa

1Fazer a requisição com requests
2Transformar a resposta em DataFrame
3Calcular o preço médio
4Identificar o produto mais caro
5Criar um gráfico de barras
6Imaginar um endpoint FastAPI que disponibilize o preço médio

07 · Exercício · solução

Solução — obter, transformar, calcular

obter e transformarpython
import requests
import pandas as pd

response = requests.get(url, timeout=10)
response.raise_for_status()

df = pd.DataFrame(response.json())
calcularpython
media = df["preco"].mean()          # 1950.0

mais_caro = df.loc[df["preco"].idxmax()]
nome = mais_caro["produto"]          # "Notebook"
df produto preco 0 Notebook 4500 1 Mouse 150 2 Monitor 1200
✓R$ 1.950,00 — preço médio
✓Notebook — produto mais caro

idxmax() devolve o índice da linha com o maior valor; df.loc[índice] devolve a linha inteira — não só o preço.
